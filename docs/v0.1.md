# v0.1: a playable alpha

v0.1 is reached when a small group can play an evening of HL2RP on a dedicated server, and the
staff running it never have to leave the game or edit a file to keep it going.

Every line below is either checked by a command or by a named person doing a named thing. If it
cannot be checked, it does not belong here. `rewrite/game-first` was merged to `main` in both
repositories on 2026-09-19, ahead of this list being finished, once Noah replaced the old code's
required status checks with `logic`. The tag `v0.1.0` waits for every line.

## 1. It holds to its own laws

Checked by `pwsh tools/verify.ps1`, `pwsh tools/playtest.ps1` and `pwsh tools/playtest-server.ps1`,
all passing on the commit being tagged.

- [x] A client is never sent another character's name or faction it was not told.
- [x] Speech stops at its range, and a claimed position buys no reach and no hearing.
- [x] Items and tokens only move: every source and sink is named, and the token supply equals the journal's issues minus its destroys.
- [x] Every host decision, refusal and staff command is in the journal.
- [x] Characters, what they know, their state, holders and doors survive a restart.
- [x] The two-client test passes three runs in a row. Done 2026-09-19 on `d347be7` and again on `c472618` after the movement audit changed: 56 of 56, seven runs running. The run that once judged a character from the wrong place was explained by a kept journal: a person at the machine had driven a test client. Test clients now suppress input.

## 2. A person can play it without being told the keys

Checked by Noah playing the scene alone for fifteen minutes and ticking each line. Nothing here
has ever been clicked by a person; every test drives the game through `DevCommands`. The editor
test does save pictures of each panel (`hexagon-look-*.png` in the temp folder), and those have
been looked at: that is how the vendor became a price list. Pictures are not play.

Keys, as the HUD's own legend shows them: Enter talks, Q is the inventory, E uses what you look at,
F names everything else it offers, Tab is the staff panel, the left mouse button strikes or fires.

- [ ] Create a character, enter the city, and leave it.
- [ ] Say, whisper, yell, emote and talk out of character, and read the replies.
- [ ] Move, hold, use and drop items; pick one up; put one in the crate and take it back.
- [ ] Buy from and sell to the vendor, and see each price before paying it.
- [ ] Open, lock and buy a door.
- [ ] Find every verb a target offers, and choose one deliberately, from a menu: not from memory of number keys.
- [ ] Open the staff panel, read the journal, and move a character.
- [ ] No panel traps the cursor, swallows a key, or has to be closed by restarting.

## 3. What the old game had that an evening needs

Each arrives the way everything else did: as a playable slice with its own play-test section.

- [x] **Stacks.** Identical items share a slot up to a limit set on the item. Splitting and merging are transfers and are journaled. A pistol and thirty rounds fit in a starting inventory. Checked by both play tests and `IdenticalThingsPileUpAndEveryOneOfThemIsAccountedFor`.
- [x] **Radio.** Holding a radio tuned to a frequency carries speech to others holding one tuned the same, and to nobody else. Someone standing next to the speaker hears it as ordinary speech. Checked between two clients 1260 units apart, with a retune and a bystander.
- [x] **Looks.** A faction sets its members' model. An item asset sets the model it has in the world and in hand. A downed character, a body, a crate and a vendor are not boxes. Checked in the editor test's pictures. s&box ships no weapon models, so HL2RP's pistol, keycard and radio are still tinted blocks until someone picks models for them in the asset browser; that is authoring, not code.
- [ ] **What is in hand is seen.** A second player can tell, by looking and without a test driver, that someone has drawn a pistol. Built: the two-client test confirms the second client is sent it, and a picture shows a two-handed pistol stance from the front. Ticked when a second person sees it, in section 4's session.

## 4. It runs somewhere that is not Noah's PC

Checked once, by Noah and at least two other people on their own Steam accounts. The evening is
scripted in [hosting.md](hosting.md), which also says what about hosting has not been tried.

- [ ] `sbox-server` hosts HL2RP on a machine nobody is playing on, and three accounts join over the Steam relay, not loopback.
- [ ] A one-hour session ends with no exception and no `[store]` or `[journal]` warning in the server's output.
- [ ] Staff whitelist an account, give an item, move a character and settle one dispute from the journal, without touching the server's console or its files.
- [ ] The server is stopped and started mid-session and everyone returns to where, and how, they were.
- [x] The data folder is copied while the server runs, and a server started on the copy loads every character. Checked by the two-client test on every run, on one machine. Worth doing once more by hand in the session.

## 5. Someone else could pick it up

- [x] The README's setup steps, followed exactly on a clean checkout, end in a running game. Done 2026-09-19 with fresh clones of both repositories in a temp folder: the build verified and the editor play test passed 70 of 70 from the clone. Same machine, so it does not prove the prerequisites list is complete.
- [x] Unit tests run on every push, on a hosted runner. The play tests stay local, because they need s&box. The workflow is `.github/workflows/tests.yml`; its first run, on 2026-09-19, passed 31 of 31 on Linux.
- [x] `docs/decisions.md` has no entry that the code contradicts. Read against the code 2026-09-19; seven entries that later decisions had changed were corrected in place.

## Not in v0.1

Deliberately left for later, so their absence is not a reason to hold the tag: the scanner, civic
records, forcefields, ration dispensers and the Combine overlay (HL2RP's own work); recoil, cover
and a restraint struggle; whitelist applications in game; an operator view of the money supply;
journal rotation; migrating saved data across a schema change; a second game built on the library;
publishing `kbj.hexagon` as a package. The last two are what v1.0 is for.
