# Security model

The host treats every network message as intent. `RpcGuard` constructs an immutable actor from `Rpc.Caller`; replicated platform IDs are display metadata only. Application connection handling is delayed until the authenticated caller binds a fresh `ClientSessionNonce`. Commands and every returned hello, result, state, character-list, and chat packet carry the exact client nonce plus host `ConnectionEpoch`; reconnects reject every delayed packet from the old scope. Command transports live on a host-owned services object. Player bodies may remain client-owned for input, but all server-authored synchronized properties use `SyncFlags.FromHost`.

Authenticated command attempts pass through a weighted per-connection token bucket before payload construction: 16-unit burst, 8 units/second refill, and at most 16 active requests. Rejected, duplicate, and malformed attempts are not refunded. Framework payload validation allows at most 32 map entries, 96-character keys/identifiers, 4,096 UTF-16 code units per string/choice, valid Unicode, and 16 KiB aggregate UTF-8; feature limits may be stricter.

Inventory access is transient and external to persisted inventories. Commands require explicit `View`, `Move`, `TransferIn`, `TransferOut`, `Use`, `Drop`, or `Sell` capabilities. The host proves source membership, destination access, session binding, policy, and capacity before one transaction. Character changes and disconnects revoke old grants and sessions.

Continuing interactions are bound to connection, active character, target, and server-issued capabilities. Coordinates and ranges must be finite, distance uses widened arithmetic, and invalid/out-of-range geometry fails before line-of-sight, policy, or action code. Distance and line of sight are reconstructed on the host, checked at start and completion, revalidated at four hertz, and expire after sixty idle seconds. Timed actions are limited to one per connection/character, five minutes plus a 15-second completion grace, and are indexed and swept on every relevant lifecycle boundary. Target destruction, movement, policy changes, character changes, close, and disconnect revoke them.

Unknown schemas, modules, definitions, actions, permissions, codecs, targets, and handlers fail closed. Policy exceptions deny with diagnostics; post-commit event exceptions are isolated because the mutation is already durable.

Chat is Unicode-normalized, limited to 512 Unicode scalars, and rate-limited per connection. All chat entry points share one reservation-capable global bucket; transactional entry points hold admission through commit and release it on failure. Pending reservations remain debited across refill windows, closing concurrent double-credit bypasses. Recipient calculation uses one immutable live-inventory capture and never performs persistence reads.

Transactions can register read dependencies with `RequireUnchanged`. Those dependencies are validated under the same commit gate as writes, so a membership or authority proof that changes between validation and commit aborts the operation. A dependency-only unit of work performs no write, does not advance the sequence, and creates no synthetic revision.
